# Архитектура «Анонимайзер данных»

## Каноническая схема (по требованию задания)

> Формат сдачи: **Источник данных → База знаний → LLM (Prompt System) → Интерфейс**.

```mermaid
flowchart LR
    SRC["📥 Источник данных<br/>• текстовые сообщения<br/>• файлы .txt / .pdf / .docx<br/>(Telegram)"]
    KB["📚 База знаний<br/><b>правиловая БЗ</b><br/>(вместо Vector DB)<br/>• regex-паттерны<br/>• 14 классов сущностей<br/>• правила замены"]
    LLM["🧠 LLM (Prompt System)<br/>OpenAI gpt-4o-mini, T=0<br/>system + user prompt<br/>с маркерами &lt;&lt;&lt;DOC&gt;&gt;&gt;…&lt;&lt;&lt;END&gt;&gt;&gt;"]
    UI["💬 Интерфейс<br/>Telegram-бот<br/>(python-telegram-bot)"]

    SRC --> KB --> LLM --> UI
    LLM -. "аудит-лог" .-> LOG["🗒️ logs/prompts.jsonl"]
```

### Соответствие компонентов проекту

| Канонический блок | Реализация в проекте | Файл |
|---|---|---|
| **Источник данных** | Сообщения и документы пользователя в Telegram; извлечение текста из `.pdf` / `.docx` / `.txt` | `src/bot.py`, `src/extractors.py` |
| **База знаний** | Правиловая БЗ: regex-паттерны структурных ПД (email, телефон, ИИН, БИН, БИК, IBAN, карты, адреса, юрлица) + словарь из 14 классов сущностей и правил замены, зашитый в system-промпт | `src/anonymizer.py` (regex-слой), `src/prompts.py` (правила в system-промпте) |
| **LLM (Prompt System)** | OpenAI Chat Completions, `gpt-4o-mini`, `temperature=0`; system + user prompt; ввод обрамлён маркерами `<<<DOC>>>…<<<END>>>` для защиты от prompt injection | `src/anonymizer.py` (`Anonymizer`), `src/prompts.py` |
| **Интерфейс** | Telegram-бот: принимает текст/файлы, возвращает результат **в исходном формате** (`.docx → .docx`, `.pdf → .pdf`) | `src/bot.py` (`handle_text`, `handle_document`, `_send_as_docx`, `_send_as_pdf`) |

> **Почему «правиловая БЗ», а не Vector DB.** Классический RAG-паттерн с векторным поиском в этой задаче не применим: LLM не извлекает релевантные документы из корпуса, а **трансформирует входной текст по фиксированным правилам замены**. Поэтому роль базы знаний играет детерминированный набор правил (regex-паттерны + 14 классов сущностей + правила замены в system-промпте). Это сознательное архитектурное решение: оно делает систему **дешевле, быстрее и воспроизводимее**, чем эквивалент с векторной БЗ.

## Развёрнутая схема (внутреннее устройство)

```mermaid
flowchart LR
    U["👤 Пользователь<br/>(Telegram)"] -->|"текст / .txt / .pdf / .docx"| TG["🤖 Telegram Bot<br/>python-telegram-bot"]
    TG --> EX["📄 Extractor<br/>(pypdf / python-docx)"]
    EX --> RX["🛡️ Regex-предфильтр<br/>email, телефон, ИИН/БИН, карты"]
    RX --> PB["🧠 Prompt Builder<br/>system + user prompt"]
    PB --> LLM["☁️ OpenAI API<br/>(gpt-4o-mini)"]
    LLM --> CLN["✏️ Очищенный текст"]
    CLN --> TG
    TG -->|"анонимный документ"| U

    PB -. "лог промпта" .-> LOG["🗒️ logs/prompts.jsonl"]
    LLM -. "лог ответа" .-> LOG
```

## Компоненты

| Слой | Файл | Что делает |
|------|------|-----------|
| Telegram I/O | `src/bot.py` | Принимает сообщения и документы, отдаёт ответ |
| Извлечение текста | `src/extractors.py` | Достаёт текст из `.txt`, `.pdf`, `.docx` |
| Regex-предфильтр | `src/anonymizer.py` (`regex_prefilter`) | Маскирует email, телефоны, ИИН, БИН, карты, IBAN |
| LLM-слой | `src/anonymizer.py` (`Anonymizer`) | Дочищает контекстные сущности (ФИО, адреса, даты рождения) |
| Промпты | `src/prompts.py` | System + user prompt с правилами замены |
| Конфигурация | `src/config.py` | Загрузка `.env` |
| Логи промптов | `logs/prompts.jsonl` | JSONL-лог: запрос, ответ, токены |

## Поток данных (по шагам)

1. Пользователь отправляет текст или файл в Telegram.
2. `bot.py` принимает апдейт и (если файл) вызывает `extractors.extract_text`.
3. `regex_prefilter` маскирует структурные ПД — это страхует от ошибок LLM
   и снижает счёт за токены.
4. `Prompt Builder` собирает `system_prompt` (правила) + `user_prompt` (текст
   между маркерами `<<<DOC>>>` / `<<<END>>>`).
5. Запрос уходит в OpenAI Chat Completions (`temperature=0` для воспроизводимости).
6. Ответ + метаданные (модель, токены) пишутся в `logs/prompts.jsonl`.
7. Бот возвращает анонимизированный текст пользователю (если длиннее 3500
   символов — кусками).

## Почему гибрид «regex + LLM»

| | Только regex | Только LLM | Гибрид |
|---|---|---|---|
| Телефоны/email/ИИН | ✅ 100% | ⚠️ может пропустить | ✅ |
| ФИО, адреса | ❌ | ✅ | ✅ |
| Стоимость | $0 | $$ | $ (меньше токенов после префильтра) |
| Воспроизводимость | ✅ | ⚠️ | ✅ |

## Этические/приватные риски

- **Утечка через провайдера LLM.** Текст уходит в OpenAI. В отчёте указать
  этот факт и оговорить, что для боевого использования нужна локальная LLM
  (Llama 3, Qwen) или контракт с провайдером с no-training-режимом.
- **Ложноотрицательные срабатывания.** LLM может пропустить редкое имя или
  казахскую транслитерацию. Поэтому regex-слой обязателен как страховка.
- **Reversibility.** Плейсхолдеры `[ИМЯ]` неуникальные — это by design:
  невозможно восстановить личность по выводу.
